# 02 · 数据模型

## 设计原则

**1. 库存流水是唯一真相来源**

所有库存变动（进货、销售、退货、损耗、未来的盘点差异）都写入只追加的 `stock_movements`。`inventory` 表只是这张流水的物化快照，任何时候都能从流水重算出来。

这条是为了可回溯性。小店软件最后翻车基本都翻在"账对不上又查不出原因"。

**2. 成本快照不可变**

`sale_items.unit_cost_base` 记录成交那一刻的加权成本，`sales.cost_amount` / `gross_profit` 同理。历史单据的成本是既成事实，不是计算结果。

**3. 业务日期与记录时间分离**

`biz_date`（可改）用于所有报表统计，`created_at`（不可改）仅用于审计追溯。

**4. 允许负库存**

不做写入拦截，仅在展示层标红提醒。

## 移动加权平均成本算法

### 进货时

```
new_qty = old_qty + in_qty

if new_qty <= 0:
    new_avg = in_cost        # 进完仍为负或归零，历史成本无参考意义
elif old_qty <= 0:
    new_avg = in_cost        # 进货前是负库存或零库存，旧均价无效
else:
    new_avg = (old_qty * old_avg + in_qty * in_cost) / new_qty
```

**必须显式处理 `old_qty <= 0` 的分支**。因为允许负库存，标准加权公式在这里会算出负成本或除零。

### 销售时

```
avg_cost 不变
qty_base -= sale_qty_base      # 允许变负
```

库存变负后继续销售，仍沿用最后已知的 `avg_cost_base` 估算毛利。这是有偏差的，但比拒绝记账好——下次进货时成本会自动校正回来。

### 精度

- 成本字段统一 `decimal(10,4)`。整条进价 550 / 10 包 = 55.0000，但 333 / 6 瓶 = 55.5000，两位小数会累积误差
- 金额字段 `decimal(12,2)`
- **不要用浮点数**

## 欠款与核销规则

### 账务模型

赊账不是独立模块，而是销售单的结算属性：

```
某张单已核销额 = SUM(payment_allocations.amount WHERE sale_id = 该单)
某张单未结清额 = sales.total_amount − 已核销额
客户总欠款     = SUM(该客户所有单的未结清额)
客户账龄       = 今天 − 最早一张未结清单的 biz_date
```

### FIFO 自动核销

老板的心智是"老王还了 500"，不关心具体是哪几笔。所以收款记在**客户**身上，系统自动核销：

```
1. 取该客户所有未结清的销售单，按 biz_date 升序
2. 依次核销，每核销一张写一条 payment_allocations
3. 收款金额用完即止
4. 若核销完所有单仍有剩余 → 提示「超额收款」，一期不做预收账款
```

界面默认只显示「老王共欠 ¥3,200，最早一笔 45 天前」。按单核销明细收在详情页里，需要时才看。
