# 图标

一个深绿圆角方块 + 白色酒瓶。配色取自界面主题（`packages/web/src/styles/index.css` 的 `@theme`），
和软件里是一套。

## 文件

| 文件 | 干什么的 |
|---|---|
| `烟酒台账.svg` | 完整版，瓶身带标签、标签上两条横线。48px 及以上用它 |
| `烟酒台账-small.svg` | 小尺寸版，实心瓶不开标签。16/24/32 用它 |
| `烟酒台账.ico` | 上面两个光栅化后拼成的七尺寸图标，**入库的成品** |
| `make-ico.mjs` | 把一堆 PNG 拼成 .ico |

为什么要两个 SVG：标签那一块在 16px 下只有两三个像素高，开出来是一道灰边，
整个瓶子被切成两截，反而不像瓶子。实心轮廓在那个尺寸最认得出来。

## 用在哪

三处，都指向同一个 `.ico`：

1. **网页 favicon** —— `packages/web/public/favicon.ico`。老板看到的那个
   `msedge --app` 窗口，任务栏图标取自这里，不是 exe 的图标。这处最要紧。
2. **exe 自己** —— `sea.mjs` 用 rcedit 嵌进去（只有 SEA 版有 exe）。
3. **桌面快捷方式** —— `安装.bat` 的 `IconLocation`。SEA 版指向 exe，
   非 SEA 版指向包里的 `app\烟酒台账.ico`。

改了 SVG 之后三处都要跟着更新：重新生成 `.ico`，再 `cp` 一份到
`packages/web/public/favicon.ico`。

## 怎么重新生成

光栅化这一步要浏览器。Node 侧没有 SVG 渲染器，而为了一个几乎不会变的图标去引
sharp / resvg 这类带原生二进制的依赖不划算 —— 所以 `.ico` 是**成品入库**的，
不在构建期生成。

1. 起一个静态服务把这个目录的 SVG 喂给页面（浏览器不让 `file://` 的页面
   跨文件读 SVG 再 `toDataURL`，会污染 canvas）。
2. 页面里对每个尺寸 `drawImage` 到对应大小的 canvas，`toBlob('image/png')`，
   ≤32 用 small 源、≥48 用完整源。
3. 把七个 PNG 存成 `16.png` … `256.png`，然后：

   ```
   node packaging/icon/make-ico.mjs <png目录> packaging/icon/烟酒台账.ico
   cp packaging/icon/烟酒台账.ico packages/web/public/favicon.ico
   ```

`make-ico.mjs` 不做任何像素处理 —— ICO 从 Vista 起允许直接内嵌 PNG，
所以它只写一个头加七个目录项，再把 PNG 原样接在后面。

验证：`node -e` 解析一遍 .ico，确认每一项的偏移指向合法 PNG、且 IHDR 里的尺寸
和目录项对得上。注意 `System.Drawing.Icon` 请求 256px 只会返回 128 —— 那是
GDI+ 自己的限制，不是 .ico 有问题，Windows 资源管理器能正常显示 256。
