# ly-ledger · 烟酒台账

给单店烟酒店老板用的进销存台账系统。NocoBase 作后端，自研极简 PC 前端，**本地单机运行**。

## 一句话定位

**回答老板每天最关心的四个问题**，其余一概不做：

1. 我手上有多少货，值多少钱？
2. 谁欠我钱，欠多少，欠多久了？
3. 这个月赚了多少（毛利）？
4. 哪些货压仓不动？

## 关键约束

| 维度 | 结论 |
|---|---|
| 使用者 | 单店老板一人，无店员、无多角色权限 |
| 终端 | **纯 PC 桌面 Web**（柜台电脑），键盘流操作 |
| 部署 | **本地单机**，Windows 免安装便携包，不上 Docker |
| 录入方式 | 全手工录入，**不做扫码** |
| 记账时机 | 实时为主，支持事后补录（业务日期可改） |
| 交付形态 | 自用 / 给特定一两家店，不做多租户 |
| 成本口径 | 移动加权平均 |
| 利润口径 | **毛利**（不含房租、水电、人工） |

## 技术栈

- **后端**：NocoBase 2.x（Apache-2.0 部分）+ 自研业务插件 `plugin-ledger`
- **前端**：Vite + React 18 + TypeScript + Tailwind CSS + TanStack Query
- **数据库**：SQLite（单文件，备份 = 复制文件）
- **运行**：便携版 Node + nssm 注册 Windows 服务，Edge `--app` 模式作桌面入口

## 五条设计红线

实现时不得违反，详见 [01-背景与范围](docs/01-背景与范围.md)：

1. **库存允许为负**，不做写入拦截，只标红提醒
2. **业务日期与记录时间分离**，报表一律按 `biz_date` 统计
3. **成本在成交那一刻快照冻结**，历史毛利不可因后续进货而变动
4. **结账不弹对话框**，现金单一键完成
5. **毛利不是净利**，界面必须写明

## 验收标准

功能清单不是验收标准，**操作耗时才是**：

| 场景 | 目标 |
|---|---|
| 卖一条中华（现金） | ≤ 3 秒，全程键盘 |
| 卖三样商品并挂账 | ≤ 15 秒 |
| 查"谁欠我钱" | 0 次点击 |
| 补录昨天一笔漏单 | ≤ 10 秒 |

## 里程碑

| 阶段 | 内容 |
|---|---|
| M0 | 环境搭建，NocoBase + SQLite 跑起来 |
| M1 | 8 张表在 `plugin-ledger` 中定义完成，后台可增删改查 |
| M2 | 三个事务型 action：`sales:checkout` / `purchases:receive` / `payments:collect` |
| M3 | 前端骨架：Vite 工程、登录、路由、API 客户端、键盘流基础设施 |
| M4 | 核心四页：看板 / 卖货 / 进货 / 收款 |
| M5 | **备份与恢复**：每日自动备份、U 盘备份、状态告警、恢复说明 |
| M6 | 利润报表：日月毛利、单品排行、滞销预警 |
| M7 | Windows 便携包打包 + 真实数据试用打磨 |

> M5 排在报表之前是有意的。本地部署的头号风险是数据丢失——硬盘坏了就是几年台账全没，而老板绝不会自己备份。**备份是产品功能，不是运维事项。**
