# ly-ledger · 烟酒台账

给单店烟酒店老板用的进销存台账系统。Fastify + SQLite 作后端，自研极简 PC 前端，**本地单机运行**。

## 一句话定位

**回答老板每天最关心的四个问题**，其余一概不做：

1. 我手上有多少货，值多少钱？
2. 谁欠我钱，欠多少，欠多久了？
3. 这个月赚了多少（毛利）？
4. 哪些货压仓不动？

## 关键约束

| 维度 | 结论 |
|---|---|
| 使用者 | 单店老板一人，无店员、无多角色权限 |
| 终端 | **纯 PC 桌面 Web**（柜台电脑），键盘流操作 |
| 部署 | **本地单机**，Windows 免安装便携包，不上 Docker |
| 录入方式 | 全手工录入，**不做扫码** |
| 记账时机 | 实时为主，支持事后补录（业务日期可改） |
| 交付形态 | 自用 / 给特定一两家店，不做多租户 |
| 成本口径 | 移动加权平均 |
| 利润口径 | **毛利**（不含房租、水电、人工） |

## 技术栈

- **后端**：Fastify + better-sqlite3 + Zod
- **前端**：Vite + React 18 + TypeScript + Tailwind CSS + TanStack Query
- **字体**：思源黑体 Noto Sans SC + IBM Plex Mono，**随包发布，不走 CDN**
- **数据库**：SQLite（单文件，备份 = 复制文件）
- **运行**：便携版 Node + nssm 注册 Windows 服务，Edge `--app` 模式作桌面入口

## 本地开发

前置：Node ≥ 20（实测 24.19.0）。

```bash
npm install
cp packages/server/.env.example packages/server/.env
npm start
```

访问 `http://127.0.0.1:13000/health`。启动时会自动执行未跑过的迁移，不需要单独的建表步骤。

常用命令：

| 命令 | 作用 |
|---|---|
| `npm start` | 启动服务 |
| `npm run dev` | 带热重载启动 |
| `npm run migrate` | 只跑迁移，打印当前表 |
| `npm test` | 单测 + 端到端（54 项），用内存库，不碰真实数据 |
| `npm run verify:model` | **拿真数据撞一遍数据模型的约束**，全程事务、跑完回滚 |
| `npm run typecheck` | 类型检查 |

数据库是单文件 `packages/server/data/ledger.db`。想推倒重来就删掉它再启动一次。

> 没有后台管理界面 —— 这是有意的，见 [03](docs/03-技术架构.md#没有后台管理界面)。要查底层数据，用任意 SQLite 客户端直接打开那个文件。

## 六条设计红线

实现时不得违反，详见 [01-背景与范围](docs/01-背景与范围.md)：

1. **库存允许为负**，不做写入拦截，只标红提醒
2. **业务日期与记录时间分离**，报表一律按 `biz_date` 统计
3. **成本在成交那一刻快照冻结**，历史毛利不可因后续进货而变动
4. **结账不弹对话框**，现金单一键完成
5. **毛利不是净利**，界面必须写明
6. **单据不可变**，改错走作废重建，绝不原地 `UPDATE`

外加一条启用红线：**商品库不全不能阻塞记账**。预置目录按品牌勾选导入，搜不到的商品在卖货页就地新建，不打断这笔生意。

## 验收标准

功能清单不是验收标准，**操作耗时才是**：

| 场景 | 目标 |
|---|---|
| 卖一条中华（现金） | ≤ 3 秒，全程键盘 |
| 卖三样商品并挂账 | ≤ 15 秒 |
| 查"谁欠我钱" | 0 次点击 |
| 补录昨天一笔漏单 | ≤ 10 秒 |
| 改一笔录错的单 | ≤ 10 秒 |

## 里程碑

| 阶段 | 内容 |
|---|---|
| M0 | ✅ 环境搭建，Fastify + SQLite 跑起来 |
| M1 | ✅ 11 张表建表完成，约束（不变量）有验证脚本兜底 |
| M1.5 | ✅ 商品入库三条路：预置目录按品牌勾选 · 手工清单批量导入 · 卖货页就地建 |
| M2 | ✅ 正向事务 action：`sales/checkout` / `purchases/receive` / `payments/collect`，含成本算法与 FIFO 核销单测 |
| M2.5 | ✅ **逆向 action**：作废 / 修改 / 退货 + 核销重算逃生舱 |
| M3 | 前端骨架：Vite 工程、登录、路由、API 客户端、键盘流基础设施 |
| M4 | 核心四页：看板 / 卖货 / 进货 / 收款，含单据详情与改单 |
| M5 | **备份与恢复**：每日自动备份、U 盘备份、状态告警、恢复说明 |
| M6 | 利润报表：日月毛利、单品排行、滞销预警 + Excel 导出（明细/欠款/商品） |
| M7 | Windows 便携包打包 + 真实数据试用打磨 |

> M5 排在报表之前是有意的。本地部署的头号风险是数据丢失——硬盘坏了就是几年台账全没，而老板绝不会自己备份。**备份是产品功能，不是运维事项。**
